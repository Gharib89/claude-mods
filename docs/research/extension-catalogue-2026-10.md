# Session extension catalogue, 2026-10

Research for #24 (map #21). Gathered 2026-10-06 from primary sources: the marketplace files themselves, the plugin trees on GitHub, GitHub code search, and the scan data an awesome list publishes. Every count below was measured by a command run on that date; the commands are in [Method](#method).

## Question

What session extensions exist today in the official and community plugin marketplaces, awesome lists, and GitHub repos using the function-hook mod API (`register(on)`)? For each: what it does, its shape (mod, hook plugin, skill, statusline, MCP), install route, licence, maintenance state, and whether it reads beyond its own folder (which decides install vs adopt).

## Answer in brief

- **The pool is large and young.** The two GitHub marketplaces hold 2,599 entries (official 315, community 2,284), the claude.ai Anthropic Directory lists 3,169, and the mod scan lists 1,752 function-hook mods in 951 repos. Every one of those mods was pushed in September or October 2026: the API arrived in Claude Code 2.1.287.
- **Function-hook mods in the wild: about 1,750 in at least 1,205 repos.** karanb192/awesome-claude-code-mods scanned 1,752 mods (951 repos) on 2026-10-04. My own code search found 254 more repos that import the `Register` type from `'claude-code'` and are not in that scan, so 951 + 254 = 1,205 repos is a floor, not a census: GitHub code search caps each query at 1,000 hits.
- **Shapes in the marketplaces** are mostly skills and MCP connectors. Hook plugins are 61 of 315 official entries and 630 of 2,284 community entries; only 6 marketplace entries are mods. Mods live almost entirely outside the marketplaces, in personal repos with their own `marketplace.json`.
- **The best fits for this owner bridge workflow seams between sessions and PRs**, which almost nothing in the marketplaces does: a mod that wakes a session when its PR merges (pr-relay), one that guards a file another live session just changed (collision-guard), and one that passes notices between sessions in one repo (notice-board). Context-loss tools are the most crowded class (handoff, pin, compaction steering, output trimming), and several overlap this repo's own smart-compact.
- **Three marketplaces found here are also named `claude-mods`** (HolyGrail, yash-gadodia, Arunjay4213). Adding one beside `Gharib89/claude-mods` collides on the marketplace name, so an install of those needs a renamed fork or an adopt.

## Counts by shape

Shape is read from each entry's plugin tree on GitHub: `hooks/hooks.json` with a `modules` key is a **mod**; any other `hooks.json`, inline manifest hooks, a `statusLine` in the plugin's `settings.json` or `monitors/` is a **hook plugin**; `.mcp.json` or `mcpServers` without hooks is **MCP/LSP**; `skills/`, `commands/`, `agents/` or output styles alone is **skill/command**. A plugin with several parts takes the first shape in that order.

## Reach scale

"Reads beyond its own folder" decides the verdict under ADR 0001 (`docs/adr/0001-mods-may-read-the-session-repo.md`): a mod adopted here may read the session repo only through git and `gh api` REST. The scale below is read from the mod scan's `calls` and `reach` fields for mods, and from the hook commands and README for hook plugins.

| Level | Meaning                                                                                  | Adopt here?                  |
| ----- | ---------------------------------------------------------------------------------------- | ---------------------------- |
| R0    | Own state only (`$.store`, `$.state`), engine events                                     | Yes                          |
| R1    | The session itself: transcript (`$.session.messages`), usage, model calls, prompt submit | Yes                          |
| R2    | The session repo through git or `gh`                                                     | Yes, if `gh api` REST only   |
| R3    | Other files or processes on the machine (`~/.claude`, other tools, desktop notifiers)    | No: install upstream, or ADR |
| R4    | Network beyond GitHub (third-party APIs, other model providers)                          | No: install upstream, or ADR |

Notes on the shortlist:

- **pr-relay is owner-shaped, not generic.** Its README is Japanese, it waits on one reviewer bot (`chatgpt-codex-connector`), keeps time in JST, and calls `gh pr view` (GraphQL). It has no licence, so its code cannot be adopted. It is evidence that the seam is real and buildable; gh-pane already holds the PR state it would need.
- **notice-board and pr-relay ship together**: pr-relay announces a merge to other sessions through notice-board's `/notice`.
- **Overlap with this repo's smart-compact**: claude-auto-handoff, cablate/ctx-handoff-mod, trytofly94/handoff-compact, prep-compact, agent-compact-advisor and lcm all act at the compaction boundary. smart-compact lets Claude pick the boundary; prep-compact and agent-compact-advisor steer or score it; the handoff mods replace compaction with `/clear` plus a brief.
- **Output trimming overlaps a tool already on this machine**: bash-diet, token-saver and output-flood shrink Bash output before the model reads it, which the `rtk` wrapper in this environment already does for some commands.

## The mod ecosystem: what a reader should know

- **Built-in mods are the reference.** `anthropics/claude-code/mods/` holds the source of the four mods that ship inside Claude Code: `sec-default`, `diff`, `telemetry` and `agents-md`, each a complete plugin with tests run by `claude plugin test`.
- **Mod collections are per-author marketplaces.** The largest by mod count in the scan: mako-code/gobworks (117), whyashthakker/awesome-claude-code-mods (70), KilimcininKorOglu/claude-code-mods (53), ucsandman/Agnostic-AI (20, labs and prototypes), tylergraydev/cc-mods (19), hamzafer/claude-code-mods (17), DJPalefaceSD/rostech-mods (17), lemomo-ai/lemo-mod (16). ruvnet/ruflo carries 40+ plugins with a `register.ts`, mostly ruflo-specific.
- **Licences**: three-quarters of scanned mods are MIT. HolyGrail/claude-mods and Arunjay4213/claude-mods state no licence, so their code can be installed but not adopted. context-mode is Elastic License 2.0, which is source-available, not open source.
- **Maintenance state** is not yet a filter: every mod is under six weeks old. Stars are the only quality signal, and 109 of 951 mod repos have five or more.
- **The scan is a primary source for reach**: it runs `claude plugin validate` on each mod and records the `$` calls the source makes, so its reach grade is read from code, not from a README.

## Method

All commands ran on 2026-10-06.

1. Marketplaces: `claude plugin marketplace list` names the configured ones. Both GitHub marketplaces were read from their `marketplace.json` (claude-plugins-official at `d4226d0`, claude-plugins-community at `f60f045`, both pushed 2026-10-05) and flattened to one row per entry.
2. Shapes, licences and last commits: one batched GraphQL query per 30 entries read each plugin's tree, `hooks/hooks.json`, `.claude-plugin/plugin.json` and `settings.json` at the entry's ref, plus the repo's licence, stars and default-branch commit date. 2,599 entries, 98 unresolved.
3. Mods: `data/mods.json` from karanb192/awesome-claude-code-mods (generated 2026-10-04 against Claude Code 2.1.289) for the census, reach and calls. GitHub code search, paginated: `"modules" filename:hooks.json` (515 repos), `"Register" "from 'claude-code'"` (328), the double-quoted form (107), and `"export const register" "on" "claude-code"` (539). The strong signature (the `Register` import) gives 431 repos, 254 not in the scan.
4. Install routes and licence files for the shortlist: `gh api repos/<repo>/contents/.claude-plugin/marketplace.json` and `gh api repos/<repo>/license`.
5. Awesome lists: each list's data file or README fetched with `gh api`, entries mapped to repos, then one batched GraphQL query per 30 repos for licence, last commit, stars and archived state; shape from each repo's tree, reach from its README.
6. The claude.ai Anthropic Directory: `~/.claude/plugins/plugin-directory-cache-v2.json`, fetched 2026-10-06.

## Caveats

- Shape detection reads fixed paths. A plugin that declares hooks or skills at custom paths in `plugin.json` may be under-counted; 182 community entries landed in "other".
- In-repo plugins of a shared repo (claude-plugins-official, ruflo) show the repo's stars, not the plugin's.
- Reach for hook plugins is read from their hook commands and README, not from running them.
- Code search is not exhaustive and not stable between runs; the 1,205-repo figure is a floor.
